# Ziel

Abschließende Absicherung: Die Gesamtsuite ist grün, ein automatisierter E2E-Lauf geht über die JSON-API, und das Moli-Kernszenario läuft auf dem **Test-Bundle** `/tmp/opencode/moli-bundle` (nie gegen `/content/pmTool/wissen`).

# Akzeptanzkriterien

- Alle Tests der App-Suite laufen fehlerfrei durch.
- Der API-E2E-Lauf (Overview → Nachtrag → Klarung → owner `ai`) liefert konsistente Werte.
- Frontmatter bleibt intakt (`type`/`title` unverändert), genau ein Nachtrag entsteht.
- `/content/pmTool/wissen` ist vor und nach dem Lauf per Hash identisch.
- `bash definitions/verify.sh /content` endet mit Exit 0.
- Das Moli-Kernszenario läuft ohne Konsolenfehler durch.
- Der Lauf ist reproduzierbar (Reset des Test-Bundles führt wieder zu Grün).

# Testfälle (TDD)

T1–T5 und T7 sind automatisierte Läufe, T6 ist das UI-Kernszenario für den `tester` (Moli-Browser).

- **T1 API-E2E:** Overview abrufen → Nachtrag anfügen → Klarung setzen → owner `ai` setzen; Werte nach jedem Schritt konsistent.
- **T2 Frontmatter intakt:** `type`/`title` unverändert, genau 1 Nachtrag.
- **T3 Bundle unberührt:** Hash von `/content/pmTool/wissen` vor/nach identisch.
- **T4 Gesamtsuite:** `python3 -m pytest definitions/app/tests -q` → Exit 0.
- **T5 Verify:** `bash definitions/verify.sh /content` → Exit 0.
- **T6 Moli-E2E:** Übersicht öffnen → Aufgabe öffnen → Nachtrag einfügen → Marker sichtbar → Klarung setzen → zurück zur Liste → owner `ai` prüfen; keine Konsolenfehler.
- **T7 Reset-Fähigkeit:** Test-Bundle zurücksetzen und erneut laufen → reproduzierbar grün.
